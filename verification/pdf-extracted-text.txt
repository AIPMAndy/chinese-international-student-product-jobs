产品岗位的申请材料，要回答四件事：你理解了谁的问题，为什么做这个方案，放弃了什么，以及你怎样
把事情推进到可验收的状态。
先别打开作品集软件。找三条你真想申请、地点和级别接近的 JD。把硬条件、工作职责、优先项、未说明
事项分开。再选材料。
1.1 十五分钟拆一条 JD
输入： 雇主官方职位链接、职位编号、你的毕业日期、在读状态、可到岗日期、现有工作授权情况与真实
经历清单。
操作：
1. 保存职位标题、地区、编号和当天日期。链接跳转后重新核对标题，避免把搜索摘要当成当前正文。
2. 圈出必须满足的条件：学历、毕业区间、工作授权、语言、现场办公、实习长度、经验要求。不能确
认的标“待确认”，不能自动标“满足”。
3. 把每条工作职责改写成一个动作，例如“把用户投诉转成优先级决策”。不要只留下“沟通能力”“
产品思维”。
4. 为最关键的三项动作各选一份材料。注明材料类型、本人贡献、真实或模拟、结果有没有发生。
5. 区分 required/minimum 与 preferred。优先项可以讨论可迁移证据；硬条件不靠精美作品集抵消。
产出： 一张岗位拆解表、一段不超过一百字的申请判断、三份最相关证据的链接。
验收： 陌生人读完后，能知道你为什么投这个岗位，最大的缺口是什么，哪条资格仍需确认。
失败处理： 找不到官方正文就暂存为线索；毕业区间不符就换批次或岗位；不清楚工作授权就写明问题并
向学校国际学生办公室、主管机关或雇主招聘方核实。不要“先填符合再说”。

WITH first_views AS (
  SELECT e.user_id, MIN(e.event_ts) AS first_view
  FROM events e JOIN users u USING(user_id)
  WHERE u.is_test = 0 AND e.event_name = 'flow_view'
  GROUP BY e.user_id
), cohort AS (
  SELECT * FROM first_views
  WHERE first_view >= '2026-11-01 00:00:00'
    AND first_view < '2026-11-02 00:00:00'
), outcomes AS (
  SELECT c.user_id,
    MAX(CASE WHEN e.event_name = 'confirmed'
      AND e.event_ts >= c.first_view
      AND e.event_ts < datetime(c.first_view, '+24 hours')
      THEN 1 ELSE 0 END) AS activated
  FROM cohort c LEFT JOIN events e USING(user_id)
  GROUP BY c.user_id
)
SELECT COUNT(*) AS eligible_users,
       SUM(activated) AS activated_users,
       ROUND(100.0 * SUM(activated) /
             NULLIF(COUNT(*), 0), 1) AS activation_pct
FROM outcomes;

操作：

3. 一次关键取舍
我比较了三种办法：继续使用表格和日历、制作有规则的人工核对原型、让 AI 自动抽取并判断。
表格的优点是学习与维护成本低，应保留为基线。规则原型可以清楚展示未知项和阻塞原因，便于检验本
轮假设。AI 自动化可能减少录入，但错误补全日期、时区或资格会让用户得到虚假确定性；在没有来源和
评测之前，不把它放进当前范围。
我选择规则原型，但接受一个代价：用户仍须人工录入与核实。如果真实研究显示它没有比表格更有帮助
，就停止增加功能，把成果收敛为一个模板。

操作： 保留职位原名；把“必须”“优先”“职责”分开；复制窗口原文，另记时区；不要把岗位层级从

产出： 每个目标岗位一行，关键要求可另增行。
验收： 任一要求能回到官方原文；未知条件有待核实动作；毕业时间不套其他国家经验。
失败处理： 页面失效时保留历史样本标签，寻找当前岗位；没有正文不能标成已核验。
要求性质建议使用：硬门槛、优先条件、工作职责、待核实。申请窗口原文不能用自己的内部截止替代。
2. 能力证据表
输入： 已拆解 JD 和本人项目。
操作： 一条要求对应一个最强证据，填写个人动作与证据强度，再写不能证明的部分。
产出： 一张能够指导补材料的缺口表。
验收： 链接可以打开；读者能分清经历、能力、表达和资格缺口。
失败处理： 找不到证据就写缺口，不用课程名或工具名代替真实动作。
来源强度可写：真实记录、经许可的团队产物、个人复盘、模拟材料、未来计划。它们不是同一强度。
3. 研究观察表
输入： 经同意的匿名笔记、观察记录或明确标注的模拟素材。
操作： 原话与解释分列；记录反例；每条保留来源与公开范围。
产出： 可回溯的材料台账。
验收： 不把模拟编号变成参与者编号；不混淆作者判断与参与者表达。
失败处理： 没有公开许可时只保留去敏摘要或不公开；没有采集记录时不写访谈结论。
4. 决策日志
输入： 一个尚待决定的问题与当时可用证据。
操作： 写至少两个选项、最终选择、代价和推翻条件。
产出： 可解释“为什么”的记录。
验收： 推翻条件是可观察证据；没有为了美化结论删掉反例。
失败处理： 无法说明代价时重做比较；未知影响保持未知，不补精确评分。
