# OfferTrail 原型规格

版本：1.0.0｜2026-11-13｜作者：AI酋长Andy

**性质：原创教学模拟。** 示例雇主、申请、材料和截止日期均为虚构。原型只演示本地核对，不连接招聘系统，不发送申请，不判断工作许可。

## 1. 一句话范围

帮助跨时区申请者在提交前看清：截止信息是否明确、材料是否齐备、仍有什么需要人工核对。

## 2. 固定样本

| ID | 虚构岗位 | 原始截止信息 | 时区 | 北京时间示例 | 初始阻塞 |
| --- | --- | --- | --- | --- | --- |
| APP-01 | 示例雇主 A · Product Intern | 2026-11-20 17:00 | Europe/London | 2026-11-21 01:00 | 作品集待补；工作许可要求待核实 |
| APP-02 | 示例雇主 B · APM | Friday end of day | 未确认 | 不展示推定时间 | 日期与时区待确认 |
| APP-03 | 示例雇主 C · Junior PM | 2026-11-24 17:00 | America/New_York | 2026-11-25 06:00 | 简历待更新 |

此处转换仅用于原型测试。生产系统应使用 IANA 时区数据库，处理夏令时、无效本地时间与重复本地时间；不要把城市名写死成全年固定 UTC 偏移。

## 3. 数据字段

| 字段 | 类型 / 示例 | 规则 |
| --- | --- | --- |
| application_id | APP-01 | 稳定 ID |
| employer_label | 示例雇主 A（虚构） | 不对应真实雇主 |
| role_title | Product Intern | 展示原始岗位名称 |
| deadline_original | 2026-11-20 17:00 | 保留原文，不静默改写 |
| deadline_zone | Europe/London | 缺失时不得猜测 |
| deadline_utc | 2026-11-20T17:00:00Z | 只有日期、时间、时区明确才生成 |
| source_status | simulated / pending / checked | 示例始终保留 simulated 标记 |
| source_reference | 教学模拟来源，无外部链接 | 真实使用时保存官方 URL、访问日和截图路径 |
| requirements | 材料清单 | required / completed / needs_review 三态 |
| work_permission_status | pending / checked | checked 仅指本人已核对来源，不代表系统认可资格 |
| reviewer_note | 自由文本 | 不收集证件号等敏感信息 |
| review_status | blocked / ready_for_manual_check / manually_checked | 不得使用 submitted，除非另有真实提交回执 |
| last_checked | ISO 时间或空 | 本地演示时间，不能冒充雇主记录 |

## 4. 四个状态与动作

1. **申请列表。** 三张卡片展示岗位、原始截止信息和阻塞数量。点击进入具体申请。
2. **来源与材料核对。** 原文、时区、本地时间并列；勾选材料准备状态，填写核对笔记。
3. **提交前检查。** 点击“运行核对”。缺少时区、必需材料或许可核对时，显示逐条原因及返回修改入口。
4. **人工核对完成。** 仅当阻塞清空且用户主动确认后，显示“本地核对已完成”。明确“尚未向雇主提交，请回到官方申请系统提交并保存回执”。

## 5. 必须保持的交互边界

- APP-02 不自动把 Friday 解释成最近的周五，也不把 end of day 解释成 23:59。
- 缺失信息用“待核实”，不能用绿色状态或估算倒计时掩盖。
- 原型中的“工作许可已核对”是用户确认字段。它不推荐许可、不验证许可，也不代表取得工作权。
- 勾选作品集仅改变本地清单，不上传文件。
- 不要求注册、邮箱、护照、学校证明或真实申请材料。
- “重置演示”恢复三条初始样本；不会声称撤回真实申请。
- 若使用 localStorage，只存模拟状态，清楚说明可清空；若不持久化，刷新后恢复初始样本。
- 键盘可访问按钮和复选框；状态变化用文字而非仅靠颜色。
- 360px 宽度应能完成核对；表格可横向滚动，主要动作不应被遮挡。

| 编号 | 操作 | 预期 |
